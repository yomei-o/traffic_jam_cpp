# traffic_jam_cpp — 道路カメラの静止画 1 枚から渋滞かどうかを判別する

首都高のライブカメラの映像で、道路（領域）ごとに「渋滞しているか」を 7 通りの方法で判別する C++ です。
判別そのものは **静止画 1 枚** で行います。動画は、答え合わせの「参照の動き」を測るためだけに使います。

**デモ**: https://yomei-o.github.io/traffic_jam_cpp/
動画から一定の間隔で静止画を切り出し、道路ごとに判別します。首都高 竹橋JCT・呉服橋JCT の録画（背景の校正つき）入りで、手元の動画や画面共有でも動きます。
計算はネイティブと同じ `traffic_jam.hpp` と `vehicle_det.hpp` を WebAssembly にしたものです。
同じ 2 枚（0.33 秒差）で、ネイティブと全項目の値が一致することを確かめてあります（`wasm/test_node.js`）。
1 回の判別は、検出器 640 版で約 0.6 秒です（ヘッドレス Chromium）。

## 考え方：道路をまっすぐな帯に伸ばす

道路は「左の縁」「右の縁」の折れ線（手前→奥）で指定します（`cams/*.txt`）。その間を、**車線幅を物差しにした帯画像** に直してから判別します。

- 帯の列: 道路の幅を、1 車線あたり 16 列に分けます。
- 帯の行: その場所の道路幅の 1/16 ずつ奥へ進みます。

こうすると、遠くの車も近くの車も帯の上ではほぼ同じ大きさになります。長さは「車線幅の何倍か」という比で測れます。
ただし、道路の向きの見かけの縮み（俯角のぶん）は残ります。

## 方法

| | 方法 | 何を見るか | 校正 |
|---|---|---|---|
| A | エッジ密度 | 車は輪郭・窓・影で縁が多く、空いた舗装はなめらか | 背景があれば、背景にもともとある縁（白線・路面の文字）を除く |
| B | 占有率 | 舗装の色から外れた画素の割合 | 背景と画素ごとに比べる（無ければ車線ごとの舗装の色） |
| C | 車間 | 車線ごとに「車のいる行」を拾い、車と車の隙間の中央値（車線幅の倍数） | B と同じ |
| D | 台数密度 | 車線 1 本・車線幅 10 本分の長さあたりの台数（C の塊を数える） | B と同じ |
| E | 赤い尾灯 | 赤く明るい画素の割合 | なし |
| F | 検出台数密度 | 車両検出器の枠の下端（タイヤの位置）が入る車線で数えた台数密度 | 検出器（[vehicle_det_cpp](https://github.com/yomei-o/vehicle_det_cpp)） |
| G | 車頭間隔 | 同じ車線で前後に並ぶ検出の、帯の上での間隔の中央値 | 検出器 |
| R | 参照の動き（静止画ではない） | 0.33 秒前との差で動いた画素 ÷ 車の画素。占有率が 0.15 より大きく、動きが 0.35 より小さければ「渋滞」 | 答え合わせ用 |

背景（車の無い道路）は、流れている時間帯の動画から画素ごとの中央値で作ります（`--make-bg`）。
渋滞で止まっている車は中央値でも消えないので、渋滞中には作れません。

## 結果（2026-11-10 昼、首都高 2 か所 × 60 秒）

背景あり、検出器あり、3 フレームおき。値はフレームの中央値、「渋滞%」は渋滞と判定したフレームの割合です。

| 場所 / 道路 | 参照の動き（渋滞%） | B 占有率 | C 車間 | F 検出台数密度 | G 車頭間隔 | 見た目 |
|---|---|---|---|---|---|---|
| 呉服橋 / 左（空いている） | 1.59（0%） | 0.15 | 4.8 | 0.96 | 8.0 | 空いている |
| 呉服橋 / 右ランプ | 0.80（0%） | 0.47 | 0.9 | 3.1 | 1.8 | 詰まっているが動いている |
| 竹橋 / 左 | 0.82（2%） | 0.57 | 0.5 | 5.3 | 0.9 | 詰まっているが動いている |
| 竹橋 / 右 | 1.29（2%） | 0.29 | 1.2 | 4.0 | 1.4 | 混んでいて動いている |

わかったこと:

- **空いている道と詰まっている道は、どの方法でもはっきり分かれる**。空いた道は、占有率 0.15・車間 4.8 車線幅・車頭間隔 8 車線幅でした。詰まった道は、占有率 0.3〜0.6・車間 0.5〜1.2・車頭間隔 0.9〜1.8 です。
- **静止画からは速さが見えない**。録れた 2 か所は、どちらも「詰まっているが動いている」状態でした。参照の動きでは、渋滞のフレームがほとんどありません。そのため静止画の方法は、詰まった道をほぼ全部「渋滞」と判定し、参照とは合いません。止まった渋滞の映像がまだ無いので、**しきい値は決めていません**（いまの値は仮）。
- **検出器（F・G）は、車列を 1 台ずつ数えられる**。帯の上の塊（C・D）は、車間が詰まると前後の車がつながって 1 台になります。トラックの背が隣の車線にはみ出す問題もあります。検出器は枠の下端で車線を決めるので、どちらにも強いです。
- **E（赤い尾灯）は昼は効かない**。夜の映像で試す価値があります。

次の一手: 夕方の混む時間帯に、止まった渋滞を録画して、しきい値を決めます。

## 使い方

```sh
# 1. 背景を作る（流れている時間帯の動画から）
traffic_jam takebashi_60s.mp4 --regions cams/takebashi.txt --make-bg t_bg.bmp
# 2. 判別する
traffic_jam takebashi_60s.mp4 --regions cams/takebashi.txt --bg t_bg.bmp --det vehicle_det.onnx \
            --every 3 --csv t.csv --overlay t.mp4 --snap t.bmp --strips ts.bmp
```

| オプション | 意味 |
|---|---|
| `--regions f` | 道路の縁の設定（`cams/*.txt`） |
| `--bg f.bmp` / `--make-bg f.bmp` | 背景を使う / 作る（1280×720、24bit BMP） |
| `--det f.onnx` `--det-every N` | 車両検出器（F・G）。重いので N フレームおき（既定 15） |
| `--csv` `--overlay` `--snap` `--strips` | フレームごとの値 / 判定を重ねた動画 / その 1 枚 / 帯画像の確認用 |
| `--jam-edge` `--jam-occ` `--jam-gap` `--jam-density` `--jam-red` `--jam-det-density` `--jam-det-headway` | 各方法のしきい値（仮） |

重ねた絵の見方: 領域は、渋滞と言った方法の数で緑→赤に塗ります。手前の左に、方法ごとの判定を四角で並べます（A B C D E F G | R、赤＝渋滞）。
黄色の枠は帯で拾った車（C・D）、水色の枠は検出器（F・G）です。

道路の縁は、60 秒の中央値画像（車を消した背景）で路面の縁を読んで決めます。車が通る場所の地図（動き）も参考になります。
ただし、トラックの屋根は路面より上に写るので、動きの上端は路面の縁より上に出ます。

## ビルド

mp4 の展開・書き出しは [mediakit_cpp](https://github.com/yomei-o/mediakit_cpp)、検出器は [vehicle_det_cpp](https://github.com/yomei-o/vehicle_det_cpp) です。
どちらも隣のフォルダに clone してあればそれを、無ければ CMake が GitHub から取ってきます。

```sh
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release --target traffic_jam
```

## ファイル

- `traffic_jam.hpp` — 帯画像と 7 つの方法（ヘッダーオンリー、依存なし）
- `main.cpp` — コマンド（mediakit で mp4 を読み書き、vehicle_det で検出）
- `cams/` — カメラごとの道路の縁
- `wasm/` — ブラウザ用の入口（`tj_wasm.cpp`）とビルド（`build.sh`、隣の vehicle_det_cpp を使う）
- `docs/` — デモ（GitHub Pages）。録画・背景・検出器のモデルを同梱（モデルは vehicle_det_cpp と同じもの、AGPL-3.0）
